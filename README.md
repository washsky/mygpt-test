# mygpt-test

单文件运行的本地 Go 论坛与博客。首页可以浏览主题、发布文章、发表回复并上传附件；保留 `/files` 文件管理和 `/calculator` 计算器。升级二进制时，程序旁的 `mygpt-test-data` 数据目录继续沿用。

## 运行

下载 GitHub Release 中适合系统的二进制文件后直接运行，默认访问 `http://127.0.0.1:8080/`。也可使用以下参数：

```sh
./mygpt-test -addr 127.0.0.1:9090 -data-dir ./my-data
```

开发环境使用 `go run ./cmd/mygpt-test -data-dir ./mygpt-test-data`。数据目录也可通过 `MYGPT_DATA_DIR` 指定，`-data-dir` 优先。默认仅监听本机；若手动设置 `-addr 0.0.0.0:8080`，访客文章、回复及文件上传接口都可以从网络访问，目前没有完整的用户账户或反滥用机制，请仅部署在可信网络中。

## 使用论坛

首次启动会生成“公告”主题。文章和回复支持纯文本内容；选择附件后提交，程序先创建文章或回复，再逐个上传并关联附件。如果附件上传失败，页面会保留已发布内容并显示失败文件。管理员可创建更多主题，在首页的“设置”中更改站点名称、简介和访客发帖/回复开关。管理员还可编辑帖子和回复；删除内容会先移入回收站，附件关系会保留，支持恢复或彻底删除。文件删除也会进入回收站。

主题、帖子和回复旁边提供复制按钮，可复制主题信息、正文或回复内容；帖子详情也能复制可分享链接。

管理员令牌首次运行自动生成于 `mygpt-test-data/config/admin-token`，创建主题、修改设置、管理帖子回复、删除/恢复文件或清空回收站时输入即可。令牌只保存在浏览器当前会话中。把“允许访客发布帖子”或“允许访客回复”关闭后，管理员仍可用令牌发布。上传接口仍允许访客上传文件，单文件最大 20 MB；目前没有完整用户账户和反滥用机制，请保持本地监听。

文件页面 `/files` 可上传、关联已有文章或回复 ID、查看列表、预览、下载和移入回收站。单文件最大 20 MB。文本预览限制为 1 MB，支持 TXT、Markdown、LOG、JSON 格式化及 CSV 表格；PNG/JPEG/GIF/WebP 和 PDF 可以直接预览。其他类型仅下载，HTML/SVG 不会在站点来源下作为网页执行。彻底删除回收站中的文件后无法恢复。

论坛首页“设置”还提供两个默认关闭的选项：启用帖子搜索（搜索标题、正文和署名），以及启用正文资源渲染（安全显示 HTTPS 图片、链接和图片附件）。资源渲染使用 DOM 文本节点构造内容，不执行帖子中的 HTML 或脚本。

## 数据与升级

```text
mygpt-test-data/
├── files/
│   ├── uploads/             # 文件内容，随机内部文件名
│   └── metadata/            # 与旧版本兼容的 JSON 文件元数据
├── database/
│   ├── catalog.sqlite       # 主题、文章索引、回复索引、设置及附件关系
│   └── posts-YYYY-MM.sqlite # 按文章创建月份存储正文和回复
├── config/
│   └── admin-token          # 管理员令牌，首次启动自动创建
└── tmp/
```

回复跟随所属文章保存在同一月份分片；附件内容始终在 `files/uploads`，关系在目录数据库。保留并备份整个数据目录，包括 SQLite 的临时日志文件。不要在另一个程序进程中同时操作这些数据库；Android 构建采用 SQLite 点锁兼容模式，尤其不要用其他 SQLite 工具并发访问同一数据库。

旧版本上传的文件和 JSON 文件元数据会保留；回收站状态也保存在这些元数据中。帖子软删除字段会在启动时迁移到目录数据库，回复软删除字段会随对应月份分片按需升级。旧版本设置的帖子/用户占位关联不会自动变成论坛中的有效帖子关系。新的附件请从文章或回复表单上传，或在文件管理页输入真实的帖子/回复 ID。

## 使用计算器

访问 `/calculator` 使用科学计算器，默认提供两个独立计算窗口，可添加或关闭窗口并排比较结果（最多四个）。支持表达式、括号、幂与取余、pi/e、常见三角/对数/舍入函数、最近计算记录、键盘输入、深色模式和复制。窗口状态与历史仅保存在当前浏览器中；表达式由 Go 后端安全解析。

## API

- `GET /api/forum/settings`、`PUT /api/forum/settings`：读取或修改设置
- `GET /api/forum/topics`、`POST /api/forum/topics`：主题列表或创建主题
- `DELETE /api/forum/topics/{id}?move_to={target}`：管理员删除主题；非空主题需指定接收帖子的其他主题，回收站记录也会转移
- `GET /api/forum/posts?topic_id=...&limit=20&offset=0`、`POST /api/forum/posts`：文章列表或创建文章
- `GET /api/forum/posts?q=...`：搜索；需先在论坛设置中启用
- `GET /api/forum/posts/{id}`、`POST /api/forum/posts/{id}/replies`：文章、回复及其附件
- `PUT /api/forum/posts/{id}`、`DELETE /api/forum/posts/{id}`：管理员编辑文章或将其移入回收站
- `PUT /api/forum/replies/{id}`、`DELETE /api/forum/replies/{id}`：管理员编辑回复或将其移入回收站
- `GET /api/forum/trash`、`POST /api/forum/trash/posts/{id}/restore`、`POST /api/forum/trash/replies/{id}/restore`：查看或恢复帖子/回复
- `DELETE /api/forum/trash/posts/{id}`、`DELETE /api/forum/trash/replies/{id}`、`DELETE /api/forum/trash`：彻底删除回收站内容或清空
- `GET /api/files`、`POST /api/files`、`GET /api/files/{id}`、`GET /api/files/{id}/preview`：上传与读取文件
- `DELETE /api/files/{id}`、`GET /api/files/trash`、`POST /api/files/{id}/restore`、`DELETE /api/files/{id}/purge`、`DELETE /api/files/trash`：移入、查看、恢复或彻底删除文件
- `PUT /api/files/{id}/association`：更改文件关联
- `POST /api/calculate`：兼容旧版双数接口，支持加减乘除、取余与幂运算
- `POST /api/calculate-expression`：安全解析表达式，支持括号、优先级、常量和科学函数；表达式最多 256 字节；`GET /healthz`：健康检查

修改设置、创建主题、回收站操作、修改文件关联、删除或恢复文件需要请求头 `X-Admin-Token`。上传时使用 multipart 字段 `file`、`related_type=post|reply` 和实际记录 `related_id`；文章/回复表单上传会自动关联，文件管理页上传可选择关联。默认上传不关联任何内容。

## GitHub Actions

CI 和 Release 均只在手动触发时运行。CI 在 GitHub 上解析 Go 依赖、测试和编译；Release 测试通过后将最新正式版本的补丁号加一，创建版本标签，并构建 Linux、Android、Windows、macOS 的二进制文件。SQLite 使用不依赖 CGO 的驱动；Release 的 Android 构建启用点锁支持。

## 工作空间界面

论坛首页、笔记详情、回复、回收站、设置、文件资料、文件预览和计算工具使用统一导航与明暗主题。主题偏好保存在当前浏览器。

- 点击“写笔记”跳到编辑区；文字草稿自动保存在当前浏览器，成功发布后清除。附件文件不会存入草稿。
- 笔记或回复中的“管理附件”打开相应文件列表，并预填上传关联；文件的“查看来源”可以回到笔记或定位回复。
- `/files/view/{id}` 提供带导航、下载和来源入口的预览页面；原有 `/api/files/{id}/preview` 仍为嵌入预览提供内容。
- 计算窗口中的“保存为笔记”把表达式和结果带入论坛草稿，追加到已有草稿正文，仍需点击发布。
- 新增只读接口 `GET /api/files/{id}/info` 与 `GET /api/forum/replies/{id}/context`，分别用于文件信息与有效回复来源定位。

文件筛选及分页仍在客户端进行。回复定位受帖子接口当前最多返回 500 条回复的限制，未显示目标回复时会给出提示。

## 可选交互与实时连接

在“设置 → 阅读、协作与连接”中，六个新增开关均默认关闭并独立保存：

- **引用回复**：回复工具栏提供引用入口，将来源链接、署名和最多 1000 字符的正文快照插入回复草稿。可编辑引用；原回复变化不会改写已发布的快照。关闭后旧引用仍保留为纯文本。
- **正文行号**：帖子和回复按原文换行显示行号、总行数；编辑框显示光标行列。屏幕自动折行不会增加原文行号。
- **逐行复制**：每一行有独立复制按钮，复制原始文字，不携带行号或按钮文字。可单独开启，无需显示行号。
- **共享剪贴板**：论坛复制或手动发送文本可进入共享历史；支持编辑和删除。无需令牌，有效期可设置；详情见下文。
- **实时推送**：使用 `/api/events` SSE 长连接，成功修改内容后推送失效通知，页面按需读取最新数据，不定时轮询或重载整页。20 秒心跳只保活；断线退避重连，重连后重新读取当前视图。论坛和文件列表更新，回复输入及附件选择保留；编辑弹窗打开时推迟更新。设置表单不被远端更新覆盖。关闭时断开连接；其他已关闭实时功能的页面需切回窗口或重新打开，才能发现远端开启。
- **网络优化**：同源 API 请求完整接收限时 20 秒，上传限时 5 分钟；读取失败最多重试一次，发帖、回复、上传、删除等写入不自动重试。失败后提示先确认结果，防止重复操作。

剪贴板与实时开关互相独立：同时开启时显示历史更新提醒，不在实时事件中携带共享内容；只开启剪贴板时手动刷新。一个实例最多 128 个实时连接。如果使用反向代理，需要对 `/api/events` 禁止缓冲、允许长连接；服务端已设置 `X-Accel-Buffering: no`。多设备需访问同一个运行实例与数据目录；这不是跨实例同步。

新增接口：`GET /api/events`；共享剪贴板接口见下文。

建议手动验证：开启各开关后打开两台设备，发帖/回复/上传并观察另一端；断开网络后恢复；引用与单行复制；发送与接收剪贴板文本；关闭开关后确认入口和连接状态变化。新增服务端回归测试随原有手动 CI/Release 工作流执行。

## 共享剪贴板更新

开启“共享剪贴板”后，论坛的主题、帖子、回复、逐行复制，以及计算器复制，都会在尝试写入本机系统剪贴板时新增一条共享文本记录。附件在论坛详情、文件列表和预览页提供独立的“发送到共享”按钮。共享历史可以编辑文本、复制、单项删除或清空，并持久存储在 `database/clipboard.sqlite`，需一起备份。最多保留最近 50 条。

设置里的“共享记录有效期”范围为 1–10080 分钟，默认 10 分钟；修改后只影响新记录，旧记录按原到期时间清理。关闭共享剪贴板会清空历史。免管理员令牌意味着所有能访问该内网站点的设备都可阅读、编辑和清空共享内容；不要在其中放入密码或敏感信息。公开论坛本身也能读取共享历史，部署范围应与共享范围一致。

文件共享记录是对现有附件的引用，不额外复制文件。附件被删除或移入回收站后，下载入口会失效。图片历史提供“复制图片”：受浏览器安全上下文及 Clipboard API 支持限制，成功时写入本机系统剪贴板的 PNG 图像；失败时可下载。普通文件可用浏览器支持的设备分享，或下载/复制链接。浏览器不提供通用的任意文件剪贴板写入接口。

API 更新为 `GET/POST/DELETE /api/clipboard`、`PUT/DELETE /api/clipboard/{id}`；均无需令牌，但必须开启共享功能。旧单条 `PUT /api/clipboard` 客户端需要改用 `POST`。实时推送事件只携带变动路径，不包含共享内容。

## 图片回复、访客展示与紧凑布局

回复框支持从系统剪贴板粘贴 PNG/JPEG/GIF/WebP 图片、拖入文件和多选附件。发布前可查看缩略图、文件大小并移除；每个文件仍限制 20 MB。只有图片/附件也可发表，正文会使用“分享附件”。附件上传失败时保留本页重试入口，重试关联到已经发表的回复，不会再创建一条回复。刷新或关闭网页会丢失未上传的本地文件，需要重新选择。

发布后的图片附件直接显示缩略内容，即使正文资源渲染未开启；任意 HTML/SVG 仍不会作为站点脚本执行。正文内的远程资源仍受原开关控制。

访客署名可在本浏览器记住；详情显示署名首字头像、完整时间、回复楼层、附件数量及当前笔记内同署名回复数。浏览器环境开关开启时，新的帖子和回复还会记录浏览器名称与主版本、系统、设备类型、语言及浏览器时区；关闭后不再记录新内容，也不展示已有内容。不会保存完整 User-Agent、IP 或精确屏幕信息。旧内容没有浏览器详情。

帖子、回复、附件、文件列表、剪贴板历史、计算窗口及顶部导航的次要功能移入浮层式“更多操作”，展开时不会挤开正文，可点击菜单外或按 Esc 收起。所有操作仍可使用；逐行复制在鼠标悬停或键盘聚焦时显示，触屏设备保持可见。

## 手动清理 GitHub 历史

Actions 中新增 **Cleanup**，仅支持手动触发：

- `scope`：构建产物 artifacts、工作流运行 runs、旧 Release releases，或 all。
- `older_than_days`：只处理早于指定天数的项目，默认 30 天，最小 1。
- `keep_latest`：每组至少保留最新数量，默认 5，最小 1。产物按名称分组，运行按工作流分组，Release 按正式/预发布分组。
- `dry_run`：默认 true，只在工作流 Summary 列出清理清单；设为 false 才实际删除。

运行中的工作流、当前 Cleanup、最新正式 Release、草稿 Release 会保留。删除 Release 会连同其下载资产删除，但保留 Git 标签，避免现有版本递增流程重用版本号。删除工作流运行也会删除它关联的产物，所以 all 模式中运行清理可能一并移除产物保留规则单独保留的内容。

该工作流只清理 GitHub 仓库历史，不连接内网服务器，不删除论坛帖子、附件或数据库。本次没有触发实际清理；请先运行预览查看候选清单。
